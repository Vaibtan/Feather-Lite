# Domain modeling

Read [domain conventions](../../../docs/agents/domain.md) and the ADRs governing the discussion. Establish terms from actual behavior and agreed decisions; distinguish a proposed model from implemented code.

Create or update GLOSSARY.md only when resolving meaningful ambiguity. Define project-specific terms, ownership, and avoided synonyms; examples should make adjacent concepts distinguishable. Preserve consistent existing names unless a rename is justified.

Record an ADR for a consequential choice whose rationale a future reader needs. Use the next number in docs/adr and a short account of context, decision, and reason. Include alternatives or consequences only when useful. Surface conflicts with existing decisions and record supersession explicitly.

Complete with resolved terminology or a reviewable decision record. Do not create empty domain documents to satisfy a template.
