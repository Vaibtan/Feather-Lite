# Prototype

Name the question the prototype should settle and the evidence that would answer it. Reuse relevant constraints and existing decisions.

Build the smallest representative slice in a clearly identified scratch location. Use current project tools; invoke frontend design guidance only when visual design is part of the question. Keep external calls, credentials, and deployment out unless included in the request.

Exercise the scenarios that distinguish candidate designs, then report what was learned and what remains unproven. Remove scratch artifacts or retain them as explicitly labeled prototypes according to the task. Do not turn a prototype into production code or automatically commit it.
