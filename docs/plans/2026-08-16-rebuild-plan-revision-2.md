# Rebuild plan — Revision 2 (after adversarial review)

**Date:** 2026-08-16 · Amends `2026-08-16-ts-effect-rebuild.md`. An independent reviewer (fresh context, plan + PRD + SPEC only) returned 25 findings; this file records what changed. Where the two documents disagree, **this file wins**.

## Accepted — design changes

| # | Finding | Change |
|---|---|---|
| R1 | Streaming the model's text before the tool commit violates *durable-before-claim* (PRD §5.1.5, SPEC §3.1). | **Two-mode turns.** The decider streams; the orchestrator holds text until it knows the turn's mode. *Chat mode* (first delta is content): deltas stream immediately — nothing has been executed, so nothing can be claimed. *Tool mode* (first delta is a tool call): model text is **discarded**; the tool executes and commits; the orchestrator then emits its own **scripted confirmation derived from the committed record** ("Recorded: 550.00 by 2026-08-21."). Outcome confirmations are never generated by the model. A late tool call in chat mode still executes after commit and appends a scripted confirmation; the metric `late_tool_call` counts it. |
| R2 | LiveKit preemptive generation would invoke `llmNode` speculatively → duplicate `/turn` mutations. | `preemptiveGeneration: false` in the worker (as the Python already did), documented in D2. Plus turn idempotency (R6) as belt-and-braces. |
| R3 | Voice unknowns deferred to the last phase. | **New Phase 1.5 — voice tracer bullet (throwaway, before Phase 2):** minimal `@livekit/agents` worker with an in-memory fake control plane, verifies: exact `llmNode` signature/stream type in `@livekit/agents@1.6.x`, `session.say()` from inside a turn, non-interruptible disclosure, barge-in truncation visibility, `voice.AMD` presence, `userAwayTimeout`, browser join from a local page, Inference credit works on the Build plan, and whether an agent **testing harness** (`session.run`-style) exists in JS. Kept afterwards as the Phase 5 integration bed. |
| R4 | A DB transaction held open across the LLM stream. | **Three-phase turn (own ADR):** T1 — `pg_advisory_xact_lock(conv)`, reject if completed, CAS `active_turn_id`, append `USER_TURN_FINAL`, commit. Decide with **no** transaction open. T2 — lock, verify `active_turn_id`, tools + `TOOL_CALLED/RESULT` + `STATE_TRANSITION` + `AGENT_TURN` (+ finalize/outbox), commit. Then emit trailer/confirmation. |
| R5 | `speak_mode` in the trailer is too late. | SSE frames: `turn_start{turn_id}` → (`delta`)* → (`say{text, allow_interruptions}`)* → `turn_end{...}`. Interruptibility is decided per **segment**, before that segment is spoken; the worker forwards deltas into the generated reply and calls `session.say()` for `say` frames (queued after the reply). Readbacks and outcome confirmations are `say` frames, non-interruptible. |
| R6 | `/turn` not idempotent; SSE reconnect replays mutations. | Client-supplied `turn_id`; unique `(conversation_id, turn_id)`; a repeated `turn_id` re-subscribes to the same turn stream (see R7) or replays frames from memory/event log. SSE `id:` frames + `Last-Event-ID`. |
| R7 | Durability coupled to the HTTP connection. | Orchestration runs in a **detached fiber** (`TurnRunner` service, `FiberMap` by conversation) publishing frames to a per-turn `PubSub`; HTTP/console/scenario-runner subscribe. Client disconnect cannot abort writes. |
| R8 | Concurrent turns undefined. | `active_turn_id` CAS: barge-in **supersedes** (interrupt in-flight fiber; append `TURN_SUPERSEDED{turn_id, superseded_by}`); any other overlap → `409 TurnInProgress`. Scenario added. |
| R9 | AMD sequencing: Mini-Miranda recited into voicemail. | For SIP calls `onEnter` waits for `amd_result` (≤2.5 s) before speaking; MACHINE → voicemail script directly. Browser calls skip AMD. `voicemail-drop` scenario asserts Mini-Miranda **not** emitted. |
| R10 | `userAwayTimeout` is single-shot and conflates disconnect. | Worker keeps its own 2-strike silence timer (reset on transcript); `userAwayTimeout` is the outer bound; participant disconnect → `hangup` signal, not `no_input`. |
| R11 | Barge-in makes `AGENT_TURN` text a lie. | New event `AGENT_TURN_PLAYOUT{turn_id, heard_text, interrupted}` sent by the worker after playout; transcript prefers `heard_text`. `barge-in-during-agent-speech` asserts truncated text. |
| R12 | Framework `chatCtx` vs control-plane history. | D2 states: control plane is the sole history owner; worker uses `chatCtx` only to read the truncated assistant message. Leak test intercepts the **OpenAI request body** (test `LlmClient` layer), for every state before unlock. |
| R13 | Clock/timezone not injected. | `now` is a parameter everywhere in the domain; Effect `Clock`/`DateTime` in services; `new Date()` banned by lint in domain/control-plane; seed borrowers in ≥2 zones (US + IST); `DEMO_MODE` clock override on `/calls/start`; TCPA tests at 07:59/08:00/20:59/21:00 local incl. a DST day. |
| R14 | Warm transfer effectively missing. | `CallControl.warmTransfer` (stub with `TRANSFER_REQUESTED/COMPLETED`, `WARM_TRANSFER_PENDING` state, hold message) asserted in hardship/dispute scenarios; SIP transfer noted as follow-on. |
| R15 | Public URL with no auth / rate limit / spend cap. | Phase 3: bearer token on mutating endpoints, per-IP rate limits on `/voice/sessions`, `/turn`, `/calls/start`; daily spend counter → 429. |
| R16 | Voice/simulation event equivalence asserted, never tested. | Phase 5 acceptance: run scenario fixtures through the worker in text mode (JS testing harness if it exists — checked in 1.5 — else a text-input harness) and **diff `conversation_events`** against the simulation path. |
| R17 | Adjacency can't express runtime flows. | Add `CONFIRMING_OUTCOME → DISCUSSING_PAYMENT` (borrower changes mind); introduce **runtime-forced transitions** (`* → ENDING` on no-input close/hangup, `* → VOICEMAIL` on AMD) that bypass adjacency but are always evented with `triggered_by`. SPEC §8.1 amended alongside. |
| R18 | Readback precondition unenforced. | Deterministic proposal → readback → record: `propose_promise_to_pay{amount,date}` (DISCUSSING_PAYMENT) stores a pending proposal, transitions to CONFIRMING_OUTCOME and the **orchestrator** speaks the exact readback (non-interruptible). `record_promise_to_pay{confirmed:true}` (CONFIRMING_OUTCOME) takes amount/date **only from the pending proposal**; fails closed (`TOOL_REJECTED`) if none. Declining → back to DISCUSSING_PAYMENT, proposal cleared. |
| R19 | Contract drift vs PRD §9 / SPEC §12. | Keep `/api` prefix; keep `POST /api/conversations/{id}/simulate_turn` (non-streaming alias over the same runner, returns the SPEC §12.2 shape incl. `call_control_action`); `turn` is the streaming endpoint; contract-diff table lives in `packages/contracts/README.md`. |
| R20 | Real-LLM behaviour untested. | On-demand LLM regression suite (~10 cases, tolerant assertions); `TURN_DECISION_REJECTED` and `TOOL_REJECTED` rates surfaced in the console. |
| R21 | Latency budget ignores the extra hop. | Worker + server co-located; connection pool pre-warmed at call start; per-turn waterfall (EOT → T1 → first delta → first audio) recorded on the turn and shown in console + Langfuse. |
| R22 | Cut list. | Removed from active scope: `apps/edge`, Durable Objects, Queues, `metrics_snapshots` cron (metrics computed by SQL on read), Oracle VM path (README note only), keep-warm pinger (a 30-line fiber, kept), Effect 4 spike. ADRs reduced to: D1 loop ownership, D2 llmNode adapter, D-tx three-phase turn. Phase 2 split into 2a/2b. |
| R23 | Seed + demo script + console too late. | Demo script written now (`docs/demo-script.md`); idempotent `pnpm seed` (3 borrowers across zones incl. one OPT_OUT, one invalid contact, one with prior PTP history); one-screen console at the end of Phase 2a. |
| R24 | Loose ends. | Outcome-coverage badge; attempt-status lifecycle in signal handlers; simulated conversations keep a synthetic `call_attempt` (channel `simulated`), as in Python; `get_account_context` kept (SPEC §10.6) but protected context is also injected on unlock; inbound calls **out of scope** (ADR note); `backend/` kept as `legacy/` reference. |

## Rejected / adjusted

- **"`llmNode` yields `ChatChunk` objects only; bare strings are Python-only."** The `@livekit/agents@1.6` source (`agents/src/voice/agent.ts`) types `llmNode` as `Promise<ReadableStream<ChatChunk | string | FlushSentinel> | null>` — strings are allowed. Verified again empirically in Phase 1.5 rather than argued.
- **Delete `get_account_context`.** Kept — SPEC §10.6 lists it and it costs nothing.
