# Design doc templates

Write to a stable path (`docs/designs/{feature}.md` or the user's preference).
If a prior doc exists for this branch/feature, add a `Supersedes:` line — designs
form a revision chain, not a pile.

## Startup mode

```markdown
# Design: {title}

Generated by /office-hours on {date} · Branch: {branch} · Status: DRAFT
Mode: Startup
Supersedes: {prior filename — omit if first}

## Problem Statement
## Demand Evidence          ← from Q1: quotes, numbers, behaviors
## Status Quo               ← from Q2: the concrete current workaround
## Target User & Narrowest Wedge  ← from Q3+Q4: the human, and the smallest paid version
## Constraints
## Premises                 ← the agreed statements from Phase 3
## Approaches Considered    ← Approach A / B (/ C) in full
## Recommended Approach
## Open Questions
## Success Criteria
## Distribution Plan        ← how users get it + CI/CD; omit for an already-deployed web service
## Dependencies
## The Assignment           ← one concrete real-world action, not "go build it"
## What I noticed about how you think  ← 2-4 bullets quoting their words back
```

## Builder mode

Same skeleton with three changes: `Mode: Builder`; replace Demand Evidence /
Status Quo / Target User & Wedge with a single `## What Makes This Cool` (the
core delight, novelty, or "whoa" factor); end with `## Next Steps` (concrete
build tasks — first, second, third) instead of The Assignment. Keep "What I
noticed about how you think."

## Spec review loop (both modes)

Reviewer = a fresh-context subagent that sees only the document. Five dimensions:

1. **Completeness** — all requirements addressed? missing edge cases?
2. **Consistency** — do the parts agree, or contradict?
3. **Clarity** — could an engineer implement this without asking questions?
4. **Scope** — creep beyond the original problem? YAGNI violations?
5. **Feasibility** — buildable with the stated approach? hidden complexity?

Returns 1-10 + numbered issues (dimension / description / fix). Fix on disk,
re-dispatch, max 3 iterations; if the same issues recur, stop and persist them as
`## Reviewer Concerns`. Reviewer unavailable → present the doc unreviewed and say
so; the review is a bonus, not a gate.
